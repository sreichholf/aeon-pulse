# Destructible Props as world entities

Destructible scenery (**Props**, per `CONTEXT.md`) are implemented as first-class world entities in a dedicated `props` collection on `GameplayRun` / `WorldState`, not as terrain- or background-owned objects. They extend the typed collision/combat pipeline — a new `CollisionContactKind`, a `PROP_DESTROYED` `HitEvent`, and an `IProp` branch in damage resolution — so that all side effects (bullet-clear radius, score/powerup drops, hazard release, timed self-burst) fire from `GameplayRun._handleHit`. This keeps collision detection pure (ADR 0005) and world stepping inside `tickGameplay` (ADR 0006).

The first pass is **non-solid only**: props are shootable scenery with effects and do not block movement. Solid, space-opening destructible blockers were deferred because they would require mutating terrain/bounds (currently static control-point geometry), which does not fit the side-effect model and is better handled later as a separate terrain-system feature. Terrain/background-owned props and `EnemyType` overloading were rejected because both leak side effects into the wrong layer or confuse the enemy catalog, Enemy Instancer, and Wave Grammar.
